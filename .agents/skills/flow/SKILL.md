# Flow

Follow authorization rules in [AGENTS.md](../../../AGENTS.md). They apply even when this skill is loaded.

## Coordinator (main session)

- **Entry:** Natural-language product requests load this skill via `AGENTS.md`; explicit `/flow` is optional. Do not ask the user to pick methodology skills (`idea-refine`, `prd-writing`, etc.)—load the smallest set from `operations/skills.md` yourself.
- **Explore:** Read the full brief first; ask a few high-value questions per round; stop when further questioning is not worth the cost. Read current `PRODUCT.md`, `DESIGN.md`, and `ARCHITECTURE.md` before consequential product work. Use templates under `templates/` as optional section catalogs only—never publish empty headings. Capture visual references and interaction direction in `DESIGN.md` during Explore when they appear—user journeys are optional.
- **Human-readable surfaces:** When the host offers structured or visual UI (for example **AskQuestion**, **Canvas**, plan review, or cowork-style forms), use it instead of long option lists or large markdown tables for comparisons, questionnaires, and quantitative results. For complex product or engineering work, add a useful diagram or chart when it clarifies trade-offs or data. Proportional fixes stay plain chat. See [human-readable-surfaces.md](../../flow/operations/human-readable-surfaces.md).
- **Human-readable chat:** In the main conversation with the human, explain status, blockers, and next steps in plain language (what the work is and why it matters). Do not answer using internal execution shorthand alone—gate ids (**G1**), task ids (**T-3-9**), wave labels without context, or dependency formulas such as `G4 = T-3-9 + T-4-4 + T-4-3`. Those ids are correct in `docs/tasks/`, initiatives, commits, and worker briefs; translate them to outcomes before replying. Link to the tasks file when traceability helps; optional parenthetical ids only after the prose is clear.
- **GenUI (product Build):** In `apps/web`, implement generative metrics, charts, forms, and composed experiences through **`@repo/genui`** and [genui.md](../../flow/specs/genui.md)—not ad hoc model HTML. Load GenUI / AI stack skills per [skills.md](../../flow/operations/skills.md) during authorized Build.
- **Contracts:** Maintain `PRODUCT.md`, `DESIGN.md`, and `ARCHITECTURE.md` as engineering contracts ([flow.md](../../flow/flow.md#contract-maintenance)). Meaningful UI or token changes require updating `DESIGN.md` in the same change; propagate accepted design into `packages/ui` during authorized Build.
- **Shortcuts:** Interpret authorization from the whole conversation (approved spec, prototype risk acceptance, bug-fix scope)—not fixed phrase lists. Plan approval ≠ Build authorization.
- **Stages:** At boundaries, state what is established, what is uncertain, what you recommend next, and whether approval is required.
- **Delegation:** Workers return structured results to you; you integrate, verify, and communicate once. See `operations/delegation.md`.
- **External brief:** Read the human-supplied brief (URL, paste, attachment) before fixtures or secondary copies in the repo. Extract **explicit** requirements only; label **assumptions** separately. **Reconcile** brief asks with [AGENTS.md](../../../AGENTS.md), [flow.md](../../flow/flow.md) (including [Starting from an existing brief](../../flow/flow.md#starting-from-an-existing-brief)), and [journal.md](../../flow/operations/journal.md). On conflict (for example a brief implies committing a prompt log), **stop and ask**—do not silently follow only the brief or only Flow.
- **Repository role:** If root contracts are still **starter-neutral** and the brief describes substantial new product work, state whether implementation belongs in **this checkout** or a **dedicated product repo** before **Build**. If a handoff page under [operations/](../../flow/operations/) matches the situation, read it before **Build**.
- **Explore → Specify:** After **Explore** approval and before substantial **Build**, persist accepted direction per [Specify checkpoint](../../flow/flow.md#specify-approval-checkpoint)—typically `docs/initiatives/<slug>.md` and/or `docs/specs/<slug>.md`, and `PRODUCT.md` when scope changes. Use **Decided** | **Assumed** | **Open** | **Non-goals**; do not invent users, metrics, or requirements absent from the brief or human approval. Cursor plan files are **not** contracts.
- **Plan → Build tasks:** For multi-step implementation, create or update `docs/tasks/<slug>.md` (checklist + dependencies); keep the initiative to a link under `## Tasks (execution)`. Do not paste task tables into initiatives or specs. [tasks-documents.md](../../flow/operations/tasks-documents.md).
- **Setup readiness:** For install, env, or logging tasks, before declaring setup complete: confirm logging policy (gitignored local logs; Task report in chat), run only commands that match setup-only vs product discovery per AGENTS.md, and do not claim prompt logging occurred unless a local gitignored file was written when required.
- **Prompt log preference:** On the first handled task when logging is neither enabled nor declined, ask once to enable local Q/A logging; on **yes**, add the enabled block from [prompt-log.md](../../flow/operations/prompt-log.md#agentsmd-enabled-block) to root `AGENTS.md` or the repo’s primary agent entrypoint; on **no**, write `.agents/flow/local/prompt-log.declined`. See [prompt-log.md](../../flow/operations/prompt-log.md).

## Steps

1. Classify the work kind (new product, existing product, or Flow improvement). For Flow improvement, stop and use user-invoked [flow-improve](../flow-improve/SKILL.md) instead of treating it as product discovery. Choose the activity (Explore → Specify → Plan → Build → Review → Ship) from task intent. Read only the matching sections of [.agents/flow/flow.md](../../flow/flow.md).
2. Distinguish **Factory** decisions (`.agents/flow/decisions/adr/`, `.agents/flow/decisions/pdr/`) from **product** decisions (`docs/adr/`, `docs/pdr/`). Factory and product ADR/PDR numbers are independent. Reuse accepted decisions from the correct namespace and root contracts. Stop and surface conflicts before changing accepted records.
3. Load the smallest methodology skill set from [.agents/flow/operations/skills.md](../../flow/operations/skills.md) for the current activity. Read each chosen `SKILL.md` before applying it.
4. When delegation helps, follow [.agents/flow/operations/delegation.md](../../flow/operations/delegation.md) and [.agents/flow/operations/worktrees.md](../../flow/operations/worktrees.md). Plan approval is not Build authorization.
5. For UI changes, follow [.agents/flow/operations/verification.md](../../flow/operations/verification.md) and [human-readable-surfaces.md](../../flow/operations/human-readable-surfaces.md) for coordinator vs product presentation. For all coordinator replies, follow **Human-readable chat** and [Chat prose](../../flow/operations/human-readable-surfaces.md#chat-prose-coordinator)—not internal task/gate id shorthand.
6. **Prompt log (coordinator only):** `.agents/flow/prompts.txt` stays **gitignored** and must **never** be committed. Repository-root `prompts.txt` is the default log path (gitignored unless a brief requires tracking on a **product branch**). When `AGENTS.md` includes `## Local prompt log (enabled)` or a brief requires a trail, ensure **one Q/A block** per handled human request—`.cursor/hooks.json` appends on each turn when enabled; the coordinator still reconciles after delegated work. Log **questions and answers** only—no multiple-choice option lists in **Q:**. Policy: [prompt-log.md](../../flow/operations/prompt-log.md). Format: [journal.md#prompt-log-qa-format](../../flow/operations/journal.md#prompt-log-qa-format). Never erase or rewrite existing entries; never fabricate timestamps, commits, subagent work, or verification. Workers and subagents must not append. In worktrees, the parent session owns the log path ([worktrees.md](../../flow/operations/worktrees.md)).
7. **Task report:** Close every repository task with the user-visible **Task report** in [operations/journal.md](../../flow/operations/journal.md) (documentation, code, verification, Git, delegation, next action). Collect and reconcile worker returns per [operations/delegation.md](../../flow/operations/delegation.md).
8. End the response with the **Skills loaded** footer from `operations/skills.md` (include `flow` when this file was read). The footer must be the final section.

## Completion

The task respects Build, commit, push, and verification boundaries from `flow.md` and `AGENTS.md`, or the agent stops with an explicit blocker.
